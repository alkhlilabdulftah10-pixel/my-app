## المرحلة 1 — التخطيط: حدّد المشكلة قبل الكود

- **شنو المشكلة؟** مطاعم وكافيهات راينه (Rheine) تدفع عمولة عالية (Lieferando/Uber Eats ‏~30%)، أو ما عندها منيو رقمي أصلاً.
- **منو المستخدم؟**
  - الزبون: سكان راينه وضواحيها (عرب، أتراك، ألمان) يبون يتصفحون ويطلبون بسرعة.
  - صاحب المطعم: يبي طلبات بدون عمولة وبدون نظام معقد.
  - الأدمن (أنت): يضيف المطاعم والأطباق.
- **شنو الهدف؟** منصة مركزية واحدة لكل مطاعم راينه، الطلب يروح مباشرة لواتساب المطعم،
  اشتراك شهري ثابت بدل العمولة. البداية بمطعمين تجريبيين.

## المرحلة 3 — التصميم: الواجهة والبيانات والهيكلة

```
UI (React pages)            API (Floot endpoints)            DB (Postgres)
/                       →   GET  /_api/restaurants       →   restaurants
/restaurant/:id         →   GET  /_api/restaurant        →   menu_items (FK → restaurants, ON DELETE CASCADE)
/admin, /admin/:id      →   POST restaurant_upsert/delete →  users / sessions / user_passwords
/login                  →   POST auth/*
                            ↓
                    wa.me/<رقم المطعم>?text=<الطلب>   ← الطلب ما ينحفظ في DB، يروح واتساب مباشرة
```

- التصميم البصري: أبيض، نص شبه أسود، لون واحد "Bestello Blue" للأزرار والأسعار، عناصر بيضاوية (pill).
- ملاحظة مهمة: التطبيق منشور كتطبيق موبايل، فأي تغيير في الـ API لازم يبقى متوافق مع النسخة القديمة.

## المرحلة 6 — النشر: مشروعك أونلاين

Floot يستضيف التطبيق (بدل `vercel --prod` في الفيديو). قبل النشر:

1. أدخل أرقام واتساب الحقيقية للمطعمين من `/admin` → "Bearbeiten".
2. راجع v1.1 في المعاينة (اطلب طبق → تأكد أن رسالة واتساب صحيحة).
3. بعد موافقتك: Publish (من محرر Floot أو أطلب مني).

## دورة v1.2 — بيانات الزبون (الاسم / العنوان / التوصيل)

كل ميزة تمر بنفس المراحل السبع.

1. **التخطيط**: السائق ما يعرف وين يوصّل، والمطعم ما يعرف منو طلب.
2. **التحليل**:
   - توصيل أو استلام (إجباري).
   - الاسم ≥ حرفين، الهاتف ≥ 6 أرقام (إجباري).
   - العنوان إجباري **للتوصيل فقط**.
   - ملاحظة اختيارية.
   - بيانات الزبون تنحفظ على جهازه للطلب الجاي (بدون الملاحظة).
3. **التصميم**: زر "Per WhatsApp bestellen" يفتح نافذة `CheckoutDialog`، والبيانات تنضاف لرسالة
   واتساب. **بدون أي تغيير في الـ API أو قاعدة البيانات**، فالتطبيق القديم على الجوال يبقى شغال.
4. **التنفيذ** (Floot checkpoint: "v1.2: نموذج الاسم والعنوان والتوصيل قبل طلب واتساب"):
   - `components/CheckoutDialog.tsx` (جديد): `CheckoutDialog` + `CheckoutForm`.
   - `helpers/buildWhatsappOrderUrl.tsx`: معامل `customer` اختياري (متوافق مع الاستخدام القديم).
   - `pages/restaurant.$restaurantId.tsx`: الزر يفتح النموذج بدل الرابط المباشر.
5. **الاختبار**: 13 اختبار ناجح، و typecheck: clean.
   - `buildWhatsappOrderUrl.spec`: رسالة التوصيل، ورسالة الاستلام بدون عنوان وبدون ملاحظة فاضية.
   - `checkoutFlow.spec`: رفض توصيل بدون عنوان، رفض بدون اسم/هاتف، قبول طلب صحيح وحفظه بدون
     الملاحظة، تعبئة البيانات المحفوظة تلقائياً.
   - غلطة اكتُشفت أثناء الاختبار: مكتبة النافذة (Radix Dialog) ما تشتغل في بيئة الاختبار، ففصلنا
     النموذج عن النافذة واختبرناه مباشرة. تصميم أنظف أيضاً.
6. **النشر**: ⏸️ ينتظر أرقام واتساب الحقيقية للمطعمين + تجربتك في المعاينة.
7. **الصيانة**: التالي المقترح: الحد الأدنى للطلب ← ساعات العمل ← ثلاث لغات ← صور.
